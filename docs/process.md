- **PRD 4-3(라벨링 원칙) 위반 발견 및 수정**: PRD가 명시적으로 "개발자 용어를 쓰지 말라"며 예시까지 준 표(4-3절) 대비 실제 화면 문구를 대조해보니 두 곳이 정확히 그 금지 예시 그대로였음 — 알림을 다시 열었을 때 제목이 "알림 상세"(금지 예시 그대로) → **"이거 뭐야?"**로, 원문 보기 버튼이 "원문 보기"/"요약 보기"(금지 예시 그대로) → **"학교에서 온 그대로 보기"/"핵심만 보기"**로 수정. 항목 수정 버튼도 PRD가 준 정확한 문구 **"이거 아닌 것 같으면 고치기"**로 교체(기존엔 그냥 "수정"). "핵심만 정리하면"/"같이 확인하기"는 이미 PRD 문구와 일치해 그대로 둠.
- **PRD 4-5(전체 정보 구조 트리) 대비 가장 큰 결손 발견 및 보완 — "오늘 할 일"(홈) 화면 신설**: PRD가 최상위 4개 화면("오늘 할 일"/"새로 온 알림"/"같이 확인하기"/"지난 기록")을 명시했는데, 지금까지 실제로 만든 건 사실상 "지난 기록"(알림 목록+상세)뿐이었고 여러 알림에 걸쳐 "지금 당장 뭘 해야 하는지"를 한눈에 모아 보여주는 홈 화면 자체가 없었다(로그인 후 바로 알림 작성 화면으로 떨어졌음). 이번에 PRD 4-2가 요구한 3단 위계 그대로 구현:
  - `GET /api/today` 신설 — 가구 전체 알림에 걸친 체크리스트를 모아, (a) 기한 2일 이내&미완료인 "지금 해야 할 것", (b) 나 아닌 가구 구성원이 가장 최근에 남긴 조치 한 줄("누가 뭐 했는지"), (c) 전체 항목/완료 수를 함께 반환.
  - 모바일 `TodayScreen.tsx` 신설 — 지금 해야 할 것(체크 버튼 바로 옆, 탭하면 원본 알림으로 이동) → 누가 뭐 했는지(한 줄 요약) → 전체 목록 펼쳐보기(기본 접힘) 순서. 로그인 후 기본 진입 화면을 여기로 변경(기존엔 알림 작성 화면이 기본이었음). "알림 붙여넣기"/"지난 기록" 화면 양쪽에 "오늘 할 일"로 돌아가는 링크 추가해 3개 화면을 서로 오갈 수 있게 함.
- (이 라운드 변경 사항도 프로덕션 배포 지연으로 로컬 빌드/타입체크 검증까지만 완료.)
- **PRD 4-5 마지막 남은 최상위 화면 — "새로 온 알림" 신설**: 이걸로 PRD가 명시한 최상위 4개 화면(오늘 할 일/새로 온 알림/같이 확인하기/지난 기록)이 전부 존재하게 됨. "같이 확인하기"는 별도 화면이 아니라 각 알림 상세의 "같이 확인하기" 버튼으로 이미 구현돼 있던 것을 그대로 인정(PRD 4-1 표에도 "같이 확인하기"가 대응 데이터로 item_actions를 가리키고 있어, 알림별로 존재하는 것이 자연스러움).
  - `GET /api/notices`가 이제 알림마다 `hasOpened`(로그인한 내가 이 알림을 한 번이라도 연 적 있는지, `notice_events` 기반)를 같이 내려줌.
  - `NoticeListScreen`을 `mode: "all" | "unread"` 하나로 일반화(같은 목록, 필터만 다름 — PRD 4-3 "같은 기능은 같은 이름으로" 원칙을 라벨이 아니라 컴포넌트 재사용으로도 지킴). "지난 기록"에는 안 읽은 알림에 빨간 점 표시 추가. `TodayScreen`에 "새로 온 알림" 진입 링크 추가.
- **PRD 5-6(상태 목록 종합) 대비 누락 2건 보완**:
  - "에러(3회 초과, 원문만 저장 제안)": AI 요약이 연속 3번 실패하면 "핵심 정리가 자꾸 실패하네요. 일단 원문만 저장해두고..." 안내 + "원문만 저장하기" 버튼 노출(체크리스트 없이 원문만 먼저 저장). 지금까지는 실패해도 그냥 같은 에러 메시지만 반복 노출했음.
  - "전체 공통: 온라인/오프라인": `@react-native-community/netinfo` 설치, `NetworkBanner.tsx` 신설 — 오프라인이면 모든 화면 공통으로 상단에 "인터넷 연결을 확인해 주세요" 고정 배너 표시. 지금까지 네트워크 상태를 감지하는 코드 자체가 전혀 없었음.
  - "이미 입력한 내용은 기기에 임시 보관됨": 알림 원문 입력창의 내용을 타이핑할 때마다 `AsyncStorage`에 임시 저장하고, 앱을 다시 켜면 복원. 저장(요약 성공 또는 원문만 저장)에 성공하면 임시본은 지움. 완전한 오프라인 큐잉(재시도 동기화)까지는 아니지만, 앱이 꺼지거나 화면을 벗어나도 입력하던 원문이 사라지지 않는 핵심 요구는 충족.
  - 새 네이티브 모듈(NetInfo) 포함해서 APK 재빌드(1분 53초) 성공, 실기기 설치 후 **비행기 모드 on/off로 오프라인 배너가 실제로 뜨고 사라지는 것을 스크린샷으로 직접 확인**.
- **PRD 6-1/6-3(디자인 시스템 색상 규칙) 위반 발견 및 수정**: PRD가 "미완료·미열람 상태는 중립 톤만 쓰고 경고색은 절대 쓰지 않는다(다그치지 않는다)"고 명시했는데, 이번에 새로 만든 "배우자가 아직 안 봤어요" 안내 문구는 주황(경고색), "새로 온 알림" 표시 점은 빨강(에러색)으로 만들어 정확히 그 금지 규칙을 어겼음. 다만 이 프로젝트는 회색을 안 쓰기로 이미 정해둔 상태([[project-design-decisions]])라 PRD가 말하는 "중립 회색"을 그대로 쓸 수 없어, 이미 보조 텍스트에 쓰던 muted blue(#3D5A9C)를 중립색 대용으로 채택 — 두 자리 모두 교체. (에러 문구, 기한 표시, AI 확신도 낮음 경고, 로그아웃 등 나머지 빨강/주황 사용처는 전부 PRD가 실제로 경고색을 의도한 경우라 그대로 둠 — 전수 검토함.)
- **배포 지연 마침내 해소, 이번 세션 신규 기능 전체 프로덕션 검증 완료**: 오랫동안 반영 안 되던 배포가 따라잡음. 다음을 실제 프로덕션 호출로 확인함 — `notices/[id]`의 `householdMembers`/`viewedUserIds` 정상 반환, `checklist` 항목 수정(`title`/`detail`/`dueDate` 변경 + `is_edited_by_user=true`) 정상 동작, `GET /api/today`가 여러 알림에 걸친 체크리스트·배우자의 최근 조치(`recentPartnerAction`)를 정확히 집계, `GET /api/notices`의 `hasOpened` 필드 정상 반환, `source-compared` 이벤트 기록 정상. **이번 세션에 만든 백엔드 기능은 전부 프로덕션에서 검증 완료.**
